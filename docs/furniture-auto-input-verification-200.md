## 評価方法と範囲

- 家具スクショチャンネルの投稿を新しい順に確認し、従来の100家具と重複しない個別家具投稿100件を選んだ。追加分の投稿日は2025-04-16〜2026-01-01（日本時間）。認識結果を見て家具を選別していない。画像2枚以上の投稿を対象とし、雑談1件を除外した。無作為抽出ではなく、同じ投稿者・端末・シリーズが多い。
- 認識を走らせる前に全100家具の画像を目視し、正解値を固定した。所持上限は「所持 x / 上限」の分母を使用し、「作成数 1 / 作成可能数」と区別した。シリーズボーナスはオンボロ風の基準14を除いた対象家具の加算値。
- いごこち度、シリーズボーナス、寮ポイント、レアリティ、マス数、テーマ2種、寮、所持上限、マドルと一般素材9種を評価。画像に表示されない材料・価格・所持上限や、サイズが「－」のI列は正解の分母に入れない。塗料・結晶・イベント素材は今回の認識実装の対象外。
- 家具名と分類は投稿由来。テーマグラフは読まず、テーマ名・いごこち度等を使う既存設計を維持した。この検証は認識処理の評価であり、計算式の全列完成率や、実シートへの自動入力成功率ではない。
- 新規371画像はDiscord添付を原寸表示してブラウザで取得したキャプチャ。縮小表示での取得は避けたが、原添付バイトではなくJPEG再エンコードされた画像である。ローカル名は .png だが内容をJPEGとしてデコードする。画像取得メタデータの復元時に140枚の寸法をPNGヘッダーとして誤読したため、実画像デコーダーでメタデータだけを訂正した。画像バイト・正解値・認識処理は変えていない。
- 既存327画像の取得条件は [100家具の記録](furniture-auto-input-verification-100-v4.md) を参照。今回も原画像はGit管理外の `.local/samples/` に保存した。

## 分類情報・投稿内容の課題

追加100投稿のうち14件は現在の投稿解析を通らない。13件は分類の記載なし、1件は `内観・外観：壁` という未対応表記。これらは現状のBotでは画像認識の前に対象外になるため、画像の成績と自動入力成功を同一視しない。

## 実行確認・再現

検証完了後、取得方式の説明メタデータだけを `browser-native-size-png` から `browser-native-size-capture` に訂正した。採点用の正解値・画像ID・名称・区分・分類は同一で、画像バイトも変更していない。JSONには実行時と訂正後の両ハッシュを保存している。

25家具ずつ8バッチ、最大4プロセスで実行。経過時間は442.0秒。認識コード・テンプレートと正解ラベルの実行前後のハッシュ一致を確認した。自動テスト67件が成功。Northflank上の性能やBot全体の処理時間の測定ではない。

```powershell
.venv/Scripts/python.exe scripts/verify_furniture_samples.py .local/samples --labels tests/fixtures/furniture_samples_200.json --context tests/fixtures/furniture_samples_200_context.json --output .local/verification-200-v5.json
.venv/Scripts/python.exe -m unittest discover -s tests -q
```

正解ラベルは `tests/fixtures/furniture_samples_200.json`、分類の出所は `tests/fixtures/furniture_samples_200_context.json`。集計・全200家具の採用値・エラー・画像ハッシュは [JSON](furniture-auto-input-verification-200.json)、全認識根拠は `.local/verification-200-v5.json` に保存した。Discordへの投稿、本番シート書込み、push、Northflankデプロイは実施していない。
