# 家具スクショ自動入力の運用

既存のDiscord Botプロセス内でOpenCVとローカルTesseractを使う。外部の画像認識API、認識結果のDiscord返信は使用しない。DockerfileにTesseract英語データを追加済み。

## 設定

| 環境変数 | 既定値・用途 |
|---|---|
| `FURNITURE_AUTO_INPUT_MODE` | `off`。`dry_run` は認識・書込み計画の確認のみ（保存・書込みなし）。`write` は入力シートの空欄を補完 |
| `FURNITURE_AUTO_INPUT_CHANNEL_IDS` | `1290587266695036958,1294952504752082964`（家具スクショ・test）。指定時はカンマ区切りで対象を限定 |
| `GOOGLE_SPREADSHEET_ID` | 既存の家具入力スプレッドシートID。試験用コピーへ切替可能 |
| `GOOGLE_WORKSHEET_NAME` | `家具データ入力シート` |
| `TESSERACT_CMD` | PATHから検出。Windowsは標準インストール先も検出 |

既存のDiscord・Googleサービスアカウント環境変数を引き続き使用する。新しい画像APIキーは不要。`off` でも従来の家具名・分類の転記は継続し、空欄のみ補完する。新規行は必ず「未入力」とする。

管理タブ、DB、ローカルのジョブファイルは使用しない。投稿・編集イベントを受けたその処理内だけで画像と認識結果を扱い、終了後に保持しない。認識結果・候補・処理履歴の保存、履歴巡回、再起動復旧、自動再試行は行わない。通常の実行ログには投稿ID・成否・項目数・例外の型だけを出し、投稿本文・画像・認識値は出さない。

`dry_run` は入力シートを読むだけで、どのタブにも書き込まない。既存のタブやメモを作成・削除・変更しない。ローカル検証CLIのJSON出力は、運用者が別途明示的に実行した場合だけの検証用であり、Botから呼び出さない。

## 実装した認識範囲

- 投稿の家具名と既存15分類。先頭行形式と「家具名：」形式を受付。画像だけ・ショップ雑談は登録しない。
- 家具名の半角英数字・カナ・記号・空白はすべて全角にして転記する。家具名の照合は従来どおり全角・半角を同一視する。認識した数値はSheetsの数値型で記入する。
- R/SR/SSR、詳細／作成画面のテーマアイコン、登録済み寮アイコン。テーマグラフは解析しない。
- D/E/Fの同じステータス画像に由来する数値組、Iマス数、R所持上限、U単品の必要マドル。作成数1に加え、作成数0/0・必要数より少ない所持材料・無効な作成ボタンの3条件を確認できる材料不足画面に対応する。
- 一般素材9種の既存画像辞書を使用。通常照合に失敗した場合は元画像と平滑化した画像の両方を照合し、素材名の一致、絶対スコア、次点との差を確認する。未知アイコンと低一致度は保留する。
- 元のテーマ5種画像も利用。寮は詳細画面のカラー辞書に加えて、測定画面から切り出した全8寮の紋章を形状・縮尺で照合する。「なし」は寮欄のラベル一致と明示的な横棒を確認する。空白を「なし」と推測しない。
- 材料数は紫または材料不足時の黒い背景から白文字を分離し、文字の高さ32ピクセルを目標に拡大率を調整する（拡大率は1〜4倍）。低信頼・形式不一致の場合は48、24ピクセルを目標に再確認する。整数倍への丸めを避け、出力寸法を明示して字形の崩れを抑える。同じ切出し画像内で両前処理の有効な必要数が食い違った場合は、他の文字高さへの再試行を止める。紫の数量欄では二つの前処理で「所持数/必要数」の形式と右側の必要数の一致を確認する。黒い不足欄では所持数・必要数の両方の一致と、所持数が必要数未満であることを必須とする。
- マス数の「×」をOCRが落とす場合は記号を画像照合し、左右の1桁を別々に認識する。寮ポイントは紋章が数字の切出しに混ざる場合、数字部分を取り直して再認識する。
- 所持数の文字列が短い画面ではマス数欄のラベルを照合して位置を補正する。「所持1」だけの画面から上限を推測しない。前景のマス数「－」は既存シートと同じく空欄にする。短い「0/2」の上限や細いシリーズボーナス数値も、切出しを補正して二通りの前処理で確認する。
- J:Mは確認済みの既存ルールで計算。既存の数値・式は保持し、新規の空の計算セルにのみ入力不足ガード付き式を設定する。

基準となるオンボロ風内観シリーズの設置数2/6・効果14と、他寮のポイントを照合する。対応するシリーズ一覧は基準のみ、または追加シリーズ1件＋基準の2件。NRCの基準ポイントは投稿の分類が「内観・外観：壁紙」「内観・外観：床」なら27、それ以外なら36とする。分類は投稿から受け取り、家具名や画像から推測しない。分類のない投稿は従来どおり受付対象外。スクロールで隠れた一覧や基準と合わない測定値は保留する。配置画面の家具数を画像から保証する機能はないため、従来の撮影手順は必要。

いごこち度の白い数字は2種類の明るさ閾値で切り出し、高さ48ピクセルに揃えてOCRの一致を確認する。ベーシックにも専用アイコンを登録した。薄い寮なし表示は通常・平滑化照合と横棒の形状を確認し、寮ポイント0は必要に応じて紋章を除いた数字部分を両方式で照合する。

短い寮なしの横棒は、濃い部分だけで形状が確定しない場合に、2種類の閾値で縁も含めて横長であることを確認する。旧ステータス画面は白いパネルの縦横比と見出しを照合し、余白といごこち度欄の位置の違いを補正する。基準シリーズ・設置数・全寮ポイントの照合条件は共通。

Qシリーズ名、S:Tモーション、V:X期限・解放条件、テーマ塗料・結晶・イベント素材は初版では自動記入しない。返信だけの追加画像を親投稿へ結合する機能も初版では未対応。同じ投稿を編集して画像を追加するか、家具名と分類を付けて投稿する。異なる投稿の測定値は混ぜない。

## 投稿時の処理

1. 対象チャンネルの新規投稿、本文・添付の編集イベントでだけ実行する。有効な家具名・分類と画像が必要。
2. 同時に届いたイベントはプロセス内のロックで順に処理する。永続キューや常駐回収ワーカーはない。CPU処理と同期API呼出しは別スレッドで実行し、Discord接続を止めない。
3. PNG/JPEG/WebPをその場で取得・認識する。1枚15MB・1200万画素、投稿10枚・合計40MBまで。認識前後に投稿を読み直し、本文や画像が変更されていたらその処理を終了する。編集内容は別の編集イベントが処理する。
4. 既存入力シートの家具名を検索する。「未入力」の空欄だけ補完し、「編集中」「記入済」「公開済」や状態空欄の既存行、同名複数行は更新しない。未登録の家具は新規行へ記入する。
5. D/E/Fは同じ画像由来の一組で判定する。一部の手入力と矛盾すれば3列とも記入しない。他の読み取れた項目は補完できる。候補は保存しない。
6. 書込み直前にシートを再読込し、変更があれば終了する。家具データと新規行の必要な式・書式・入力規則だけを一回のbatchUpdateで反映する。タブ追加やセルメモへの追記はしない。
7. その処理内で書込み先の家具名・値・計算結果を読戻す。不一致や通信失敗はログへ状態だけ出して終了し、自動再送・後日の再開は行わない。書込みの応答を受け取れなかった場合、シートには反映済みの可能性がある。

読み取れた項目を書いてもB列は自動で記入済みにしない。未認識の項目は空欄のまま、既存の手順で手入力できる。同じ投稿が再度届いても、シート上にある家具名と値を基準に空欄だけを補うため、通常の再受信で行を増やさない。

停止中の投稿・編集や処理中の再起動で中断したものは回収しない。失敗時に再処理するには、原因を直して対象投稿の本文・画像を編集するか、家具名・分類付きで再投稿する。処理の保存がないため、投稿の家具名を変えた場合は現在の名前で照合する。旧名との対応を復元したり既存行を改名したりはしない。新しい名前が未登録なら別の家具として追加される。

認識エンジンは `furniture-v8`。更新だけで過去投稿が再処理されることはない。既存の済リアクション同期・通知・`/tellme` は別機能として維持し、その履歴参照から画像認識・自動入力を起動することはない。

サイズ欄の従来処理が保留になった場合、3文字が独立し、中央に「×」の斜線があり、数字が画像端で切れていないことを確認する。2つの明るさ閾値で文字を抽出し、高さ32ピクセルにそろえたOCRが一致・信頼度条件を満たす場合だけ採用する。家具名や「5×5」に固定した判定ではなく、既存の認識テンプレートは増やしていない。

Sheetsには読み書き全体の比較交換ロックがない。直前再読込を行うが、その後の手編集との競合窓は残る。手入力時はB列を「編集中」にし、Botは常に1プロセスで運用する。Northflankのローリング更新で旧・新Botを同時に `write` 稼働させない。複数プロセスでの分散ロックは未実装。

列見出しが変わると認識書込みを停止する。別名は `app/furniture_input/aliases.json` に明示的に登録。中黒だけ異なる未登録名は確認待ちにし、①②やキャラ名は保持する。

## ローカル検証

リポジトリ直下で実行する。Windowsでは `python` を `.venv/Scripts/python.exe` に置き換えられる。

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m compileall -q app scripts
python -m ruff check app/furniture_input scripts tests/test_furniture_input.py tests/test_furniture_recognition.py
python scripts/analyze_furniture.py detail.jpg status.jpg --post-file post.txt --output result.json
python scripts/verify_furniture_samples.py .local/samples --output .local/verification.json
python scripts/verify_furniture_samples.py .local/samples --labels tests/fixtures/furniture_samples_200.json --context tests/fixtures/furniture_samples_200_context.json --output .local/verification-200-v6.json
```

`post.txt` は家具名と分類を別行に記載。CLIはDiscord・Google Sheetsへ接続せず、候補・根拠・新規行の書込み予定をJSON出力する。実画像検証用の元画像は非公開の `.local/` に置き、Git・Dockerへ含めない。ラベル定義は `tests/fixtures/furniture_samples.json`、切出したUIテンプレートの由来は `app/furniture_input/assets/provenance.json` に記録。

100家具の `--context` は壁・床8家具の分類を渡す。4件は投稿の分類、4件は画像を目視確認した検証用分類であり、分類が欠落した投稿を実運用で自動補完する機能ではない。`source` に出所を記録している。

`tests/fixtures/recognition_crops/` は回帰テスト専用の小さなUI切抜き。家具認識のテンプレートとしては読み込まない。ローカルTesseractがない環境では実OCRテストがskipになるため、全件成功の確認にはTesseractをインストールする。GitHub Actionsではインストールしてからテストする。
